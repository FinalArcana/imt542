## **Project Overview**

This project integrates two datasets: **USDA Foundation Foods** and **BLS Average Retail Food Prices (AP series)**, to evaluate the nutritional value of foods relative to their cost. The system ingests both datasets, normalizes their units, and produces a unified JSON structure that supports downstream analysis such as protein‑per‑dollar and calorie‑per‑dollar comparisons.

The system operates in three stages:

1. **Ingest Foundation Foods nutrient data and BLS retail price data**  
2. **Normalize units and align both datasets to a shared 100‑gram basis**  
3. **Produce a structured JSON output with explicit units, provenance metadata, and derived metrics**

To keep the structure self‑describing without increasing payload size, the improved JSON includes lightweight metadata linking to the official documentation for each dataset.

---

# **1. How Our Structure Promotes Maintaining and Measuring Data Quality**

The redesigned structure improves data quality by making units explicit, aligning measurement bases, and adding minimal provenance metadata.

### **A. Explicit Value + Unit Scheme Improves Clarity**

Foundation Foods expresses nutrients as structured objects:

```json
"nutrients": {
  "protein": { "value": 21.2, "unit": "g" },
  "energy": { "value": 120, "unit": "kcal" }
}
```

Keeping this scheme prevents unit ambiguity and supports automated validation (e.g., ensuring protein is always in grams).

### **B. Shared 100‑Gram Basis Ensures Consistent Comparisons**

Foundation Foods uses a 100‑gram basis, while BLS reports price per pound.  
The improved structure converts BLS prices to:

```json
"price": { "value": 0.4467, "unit": "USD_per_100g" }
```

This alignment eliminates conversion errors and ensures nutrients and prices are directly comparable.

### **C. Lightweight Metadata Supports Transparency**

A compact `datasetInfo` block links to the official sources:

```json
"datasetInfo": {
  "foundationFoods": { "source": "https://fdc.nal.usda.gov/" },
  "bls_ap": { "source": "https://www.bls.gov/cpi/factsheets/average-prices.htm" }
}
```

This keeps the payload small while making the data sources discoverable and auditable.

### **D. Normalized Identifiers Improve Traceability**

Storing both `fdc_id` (USDA) and `series_id` (BLS) ensures consistent mapping between nutrient and price data and reduces mismatches.

# **2. How Our Structure Enables Identification and Management of Information Security Issues**

Although the datasets used in this project are public, the improved structure incorporates several design choices that help identify and manage information security issues related to data integrity and pipeline reliability.

### **A. Load Timestamps and Access Logging Detect Anomalies**

Each response includes a load timestamp, and every BLS series lookup is recorded to a SQLite access log:

```json
"sourceFetch": {
  "foundationFoods": { "loadedAt": "2025-05-01T00:00:00Z", "localFile": "data/foundation_foods.json" },
  "bls":             { "loadedAt": "2025-05-01T00:00:00Z", "localFile": "data/bls_retail_prices.csv" }
}
```

This allows the system to detect unexpected update gaps or access spikes that may indicate tampering or misuse.

### **B. Schema Versioning Prevents Unauthorized or Accidental Changes**

The structure includes:

```json
"schemaVersion": "1.0.0"
```

This enables validation against a known schema via `jsonschema` and makes structural drift detectable before it affects downstream analysis. The `/api/pair` endpoint returns HTTP 500 with details if output fails validation.

### **C. Source Links Support Authenticity Verification**

By storing the official source URLs in `datasetInfo`, the system can verify that data originated from the correct domains. This reduces the risk of ingesting spoofed or unofficial datasets.

### **D. Consistent Units and Basis Amounts Prevent Manipulation**

The structure enforces:

- explicit units for every nutrient  
- a fixed `basis_amount_g` of 100 g  
- a normalized price unit (`USD_per_100g`)  

This prevents silent manipulation such as switching kcal ↔ kJ or inserting per‑serving values.

### **E. Separation of Raw and Derived Metrics Supports Integrity Checks**

The structure stores raw nutrient and price data separately from derived metrics:

```json
"derivedMetrics": {
  "protein_per_dollar": { "value": 32.8, "unit": "g_per_USD" }
}
```

This allows the system to recompute derived values and verify that they match the stored results, helping detect corruption or unauthorized modification.

# **Appendix B — Sample BLS AP Records (Original Dataset)**

Raw records from the four BLS flat files that must be joined to reconstruct a usable price observation. Price data (`ap.data.3.Food`) is stored separately from item names (`ap.item`), area names (`ap.area`), and series metadata (`ap.series`). There are no nutrient fields, no normalized units, and no explicit basis amount.

**ap.series** (series metadata):
```tsv
series_id           area_code  item_code  series_title
APU0000706111       0000       706111     Chicken, fresh, whole, per lb. (453.6 gm) in U.S. city average
```

**ap.item** (item name lookup):
```tsv
item_code  item_name
706111     Chicken, fresh, whole, per lb. (453.6 gm)
```

**ap.area** (area name lookup):
```tsv
area_code  area_name
0000       U.S. city average
```

**ap.data.3.Food** (price observations):
```tsv
series_id           year  period  value   footnote_codes
APU0000706111       2026  M04     2.026
```

To get a single usable price for "Chicken, fresh, whole — U.S. city average — April 2026 — $2.026/lb" requires joining all four files on `series_id`, `item_code`, and `area_code`.
