# Nutrition–Cost Finder – Test Plan & Results
IMT542A Sp26 | Pete Namchaisiri

## Purpose

This document outlines the testing strategy for the Nutrition–Cost Finder, which integrates USDA Foundation Foods nutrient data with BLS Average Retail Food Prices to produce protein-per-dollar and calorie-per-dollar metrics. It serves as a living guide during implementation and an ongoing reference for data and system quality.

---

## System Overview

- **Pipeline**: Python ingest → normalize → JSON output via Flask REST API
- **Sources**: Local files — USDA Foundation Foods (`FoodData_Central_foundation_food_json_2025-12-18.json`), BLS flat files (`ap.series`, `ap.data.3.Food`, `ap.item`, `ap.area`)
- **Output**: Integrated JSON with nutrients, prices, derived metrics, and provenance metadata

---

## Test Objectives

- Verify that units are explicit and the 100g basis is consistently applied
- Confirm price conversion from USD/lb to USD/100g is correct
- Validate that derived metrics match recomputed values
- Confirm both source files are present, readable, and in the expected format
- Detect missing identifiers, unexpected record counts, or schema drift over time

## Known Limitations

- BLS price data reflects historical retail averages and may not match current market prices
- Food-to-BLS-series matching uses fuzzy name matching and may produce incorrect pairings for ambiguous food names
- FDC IDs requested in `/api/compare` that are absent from the local Foundation Foods file are skipped and returned in the `errors` array — this occurs when the bulk download version does not include a particular food record
- Metrics cover protein, calories, fiber, and fat per dollar and are descriptive only, not dietary guidance
